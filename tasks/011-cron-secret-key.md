# 011 — Cron-обновление курсов доступно по внешней ссылке без ключа

- **Статус:** done
- **Приоритет:** средний. Любой, кто знает URL, может дёргать обновление и
  нагружать сервер (и nationalbank.kz) запросами.
- **Файлы:** `refresh()` в `catalog/controller/extension/currency/nbk.php`;
  форма настроек: `admin/controller/extension/currency/nbk.php`, шаблон
  `admin/view/...`, языковые файлы `admin/language/*/extension/currency/nbk.php`.

## Проблема
`index.php?route=extension/currency/nbk/refresh` выполняет полное
обновление (HTTP-запрос к фиду НБ РК + запись в таблицу валют) для любого
клиента. Единственная защита — необязательный замок по одному IP, который
по умолчанию пуст. Без него URL можно дёргать сколько угодно и заддосить
сервер обновлениями.

Поставлено пользователем.

## Ожидаемое поведение
- В настройках модуля есть поле «Ключ защиты» с кнопкой «Сгенерировать»,
  которая заполняет поле криптостойким случайным ключом.
- Cron-URL выполняет обновление только при совпадении переданного ключа с
  сохранённым (сравнение за постоянное время). Иначе — 403 без обращения к
  фиду и БД.
- В админке показывается готовая cron-ссылка с ключом.
- Поведение при пустом ключе (старые установки после обновления модуля)
  определяет architect; при необходимости — вопрос пользователю.

## Подсказки для критериев приёмки
- Smoke: без ключа / с неверным ключом / с ключом-массивом → 403, фид не
  запрашивается, записей в БД нет; с верным ключом → `NBK: ok`.
- Форма: ключ валидируется (формат, длина), массив отклоняется, значение
  экранируется в HTML-атрибуте.
- IP-замок продолжает работать вместе с ключом.
- На коде из HEAD новые проверки падают.
- `tests/run.sh` → PASS.

## Закрыто
Конвейер architect → coder → verifier, 1 итерация, PASS по К1–К13
(Codex багов не нашёл). Проверено на PHP 7.4, 8.1, 8.3, 8.5 (8.2 и 8.4 не
установлены).

- Решения пользователя: без ключа fail-closed (403 `NBK: forbidden`), ключ
  обязателен, отключить нельзя.
- Настройка `currency_nbk_key`, формат `^[A-Za-z0-9]{32,64}\z`, в
  `validate()` сначала `is_scalar`, без trim.
- Cron: status → IP-замок → ключ (`is_string` обоих, непустой сохранённый,
  `hash_equals`) → модель. При неверном ключе фид и БД не трогаются.
- Админка: поле ключа с кнопкой «Сгенерировать» (`crypto.getRandomValues`,
  32 hex; пустое поле заполняется при загрузке страницы), cron-команда
  строится из сохранённого ключа (`rawurlencode` + `escapeAttr`), без
  ключа поле пустое и показывает placeholder. Тексты в 4 локалях.
- `install()`, `uninstall()`, `refreshEvent()` не менялись, переустановка
  модуля не нужна. После обновления на каждом VPS нужно открыть настройки,
  нажать «Сохранить» и заменить команду в crontab.
- `tests/smoke.php`: 21 cron-кейс, проверки формы; `tests/static.php`:
  генератор без `Math.random`. На коде из HEAD новые проверки падают.
