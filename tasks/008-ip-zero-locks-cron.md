# 008 — IP «0» проходит валидацию и навсегда блокирует cron

- **Статус:** done
- **Приоритет:** низкий. Нужна явная опечатка в поле IP.
- **Файлы:** `validate()` в `admin/controller/extension/currency/nbk.php`, `catalog/controller/extension/currency/nbk.php`.

## Проблема
`validate()` проверяет IP так: `!empty($ip) && !filter_var(...)`. Для
`'0'` `empty()` возвращает true, поэтому проверка пропускается и `'0'`
сохраняется. Catalog-контроллер понимает непустую строку `'0'` как
IP-замок, и cron всегда получает `NBK: forbidden`. В форме при этом ошибки
нет.

Найдено architect'ом при проектировании задачи 005.

## Ожидаемое поведение
Форма либо отклоняет `'0'` с `error_ip`, либо форма и cron одинаково
понимают `'0'` как «замка нет». Что выбрать, решает architect (и при
необходимости пользователь).

## Подсказки для критериев приёмки
- Проверка в smoke: POST `currency_nbk_ip=0` не приводит к состоянию, при
  котором cron молча получает `forbidden`.
- `tests/run.sh` → PASS.

## Закрыто
Вместе с 009 одной правкой. Конвейер architect → coder → verifier,
1 итерация, PASS по К1–К14.

- Выбрано «отклонять»: в `validate()` условие IP
  `(string)$ip !== ''` вместо `!empty($ip)`, поэтому `'0'` (и `'00'`,
  `'0.0'`) получает `error_ip` и не сохраняется. Ветка `!is_scalar`
  осталась первой, trim не добавлен.
- Catalog не менялся: уже сохранённый `'0'` по-прежнему даёт
  `NBK: forbidden` (fail-closed), чинится пересохранением формы — она
  теперь покажет `error_ip`.
- `tests/smoke.php`: ip `'0'`/`'00'`/`'0.0'`/`'abc'` отклоняются,
  `''`/IPv4/IPv6 сохраняются как есть; строка `$cron`
  `IP 0 stored before the fix` → 403.
- На контроллере из HEAD новые проверки падают.
