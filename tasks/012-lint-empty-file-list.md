# 012 — Lint в tests/run.sh проходит, даже если не проверил ни одного файла

- **Статус:** done
- **Приоритет:** низкий. Ложный PASS возможен только при сбое окружения.
- **Файлы:** цикл lint в `tests/run.sh`.

## Проблема
Список файлов для `php -l` подаётся в цикл через heredoc с
`$(find …)`. Если heredoc не создастся (нет временного каталога,
read-only окружение) или `find` вернёт пустой список, цикл не выполнится
ни разу. `lint_ok` при этом останется `1`, и скрипт напечатает
`ok   all PHP files lint clean`, хотя ни один файл не проверен.

Найдено Codex'ом при проверке задачи 010, подтверждено verifier'ом
чтением кода.

## Ожидаемое поведение
Если lint не проверил ни одного файла (или получить список не удалось),
это FAIL для данной версии PHP, а не `ok`.

## Подсказки для критериев приёмки
- Считать проверенные файлы; при нуле — `FAIL` и версия попадает в
  `failed`.
- Сбой подстановки/heredoc не маскируется под успех.
- `tests/run.sh` → PASS в обычном окружении.

## Чем закрыто
`tests/run.sh`: список `.php` собирается один раз до цикла по версиям,
код возврата `find` проверяется отдельно от `sort`. Внутри lint каждый
проверенный файл считается (пустые строки пропускаются). После цикла:
`find` упал → `FAIL could not list PHP files`, проверено 0 →
`FAIL no PHP files were linted`, проверено меньше списка →
`FAIL linted N of M PHP files`; во всех случаях версия попадает в
`failed`. Строка успеха: `ok   all N PHP files lint clean`.
Проверено: обычный прогон PASS (7.4, 8.1, 8.3, 8.5; bash 5 и /bin/bash
3.2), пустой каталог и поддельный `find` дают FAIL; версия из HEAD с
поддельным `find` давала ложный `ok`. Сбой heredoc в read-only
песочнице Codex тоже дал FAIL, а не `ok`.
