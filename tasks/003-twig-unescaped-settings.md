# 003 — Значения настроек выводятся в шаблон без экранирования (XSS)

- **Статус:** open
- **Приоритет:** средний. Уязвимость есть только в админке, но это stored XSS между администраторами.
- **Файлы:** `admin/view/template/extension/currency/nbk.twig:47`, `:55`; `admin/controller/extension/currency/nbk.php:46–64`

## Проблема
Twig в OpenCart 3.0.x создаётся с `autoescape => false`: это видно по
ручному `&quot;` в `currency_nbk_cron` (контроллер, строка 46). Поля
`currency_nbk_ip` и `currency_nbk_margins` выводятся в `value="…"` как есть.

- **margins** сохраняется без какой-либо проверки. Пользователь с правом
  modify на расширение может сохранить `"><script>…</script>`, и скрипт
  выполнится у каждого администратора, который откроет настройки модуля.
- **ip** проверяется через `FILTER_VALIDATE_IP`, но при ошибке валидации
  сырой POST возвращается в форму.
- Даже безобидная кавычка в значении ломает атрибут и вёрстку.

## Ожидаемое поведение
Все значения, которые ввёл пользователь, экранируются для HTML-атрибута.
Выбрать один способ и применять его последовательно:
- в шаблоне: `{{ currency_nbk_ip|e }}` (фильтр `e` есть во всех версиях
  Twig, которые поставляются с OC 3.0.x);
- или в контроллере: `htmlspecialchars($value, ENT_QUOTES, 'UTF-8')`.

`currency_nbk_cron` уже экранирован вручную, повторное экранирование
испортит `&quot;`. Это нужно учесть и либо оставить как есть, либо перевести
на тот же способ.

## Подсказки для критериев приёмки
- Значение `"><b>x</b>` в обоих полях выводится как текст внутри `value` и не
  разрывает атрибут. Проверка: рендер через контроллер на заглушках в
  `tests/smoke.php` (`load->view` возвращает `$data`) или чтение
  шаблона и контроллера.
- Команда cron на странице осталась прежней:
  `curl -s "https://…/index.php?route=extension/currency/nbk/refresh"`.
- `tests/run.sh` → PASS.
