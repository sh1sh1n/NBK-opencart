# 007 — sprintf('%.8f') зависит от локали: запятая вместо точки

- **Статус:** open
- **Приоритет:** низкий. OpenCart 3.0 сам `setlocale()` не вызывает, но хостинг или сторонний модуль может.
- **Файлы:** `editValueByCode()` и `refresh()` в `admin/model/extension/currency/nbk.php` (и в catalog-копии).

## Проблема
`sprintf('%.8f', ...)` учитывает `LC_NUMERIC` на PHP 7.4–8.5. При
`setlocale(LC_NUMERIC, 'ru_RU.UTF-8')` выходит `sprintf('%.8f', 0.002)` =
`"0,00200000"`. Последствия:
- `editValueByCode()` пишет в `decimal`-колонку строку `'0,00200000'`.
  MySQL её либо отвергнет, либо обрежет.
- Проверка из 004 `(float)sprintf('%.8f', $marked) > 0` получает 0, и все
  наценки молча перестают применяться.

Найдено verifier'ом при проверке задачи 004 (проверено вручную на PHP 7.4 и 8.5).

## Ожидаемое поведение
Форматирование курсов не зависит от локали: использовать `%.8F`
(не учитывает локаль) во всех местах, обе модели.

## Подсказки для критериев приёмки
- Проверка в smoke: при `setlocale(LC_NUMERIC, <локаль с запятой>)`
  (если такая локаль есть в системе, иначе SKIP с сообщением) записанные
  значения содержат точку, а наценки применяются. Локаль после проверки
  восстанавливается.
- В static: `sprintf('%.8f'` в моделях не встречается.
- `tests/run.sh` → PASS.
