# NBK — курсы Нацбанка РК для OpenCart 3

Currency-расширение OpenCart 3.0.x (код `nbk`, маршрут `extension/currency/nbk`).
Одна кодовая база для PHP 7.4–8.5: на VPS работают все эти версии.
Репозиторий: https://github.com/sh1sh1n/NBK-opencart

- Стек, инварианты, запреты и правила совместимости описаны в промптах
  агентов в `.claude/agents/`.
- Все проверки: `tests/run.sh` (static + `php -l` + smoke на каждой
  установленной версии PHP). Недостающие версии ставятся так:
  `brew install shivammathur/php/php@X.Y`.
- Бэклог: `tasks/NNN-*.md`.
- Graphify в этом проекте не используется: `graphify update` не запускать,
  `graphify-out/` не создавать.

## Порядок работы

Любая задача на изменение кода проходит конвейер
**architect → coder → verifier**. Главная сессия только оркестрирует: сама
код и тесты не пишет, файлы модуля не правит и проверок вместо verifier'а
не делает. Ведение `tasks/` и коммиты — её зона.

1. **architect** получает задачу пользователя, или путь к `tasks/NNN-*.md`,
   и возвращает план и нумерованные критерии приёмки К1…Кn. Если в плане есть
   «Вопросы пользователю» или он требует нарушить запреты (правка ядра
   OpenCart, OCMOD, переименование идентификаторов, смена формата настроек),
   остановись и спроси пользователя до передачи coder'у.
2. **coder** получает план целиком, включая критерии, и реализует его. Если
   coder сообщает, что план неверен, верни вопрос architect'у, а если это
   затрагивает решение пользователя — спроси пользователя. Счётчик итераций
   при этом не растёт.
3. **verifier** получает план, критерии и отчёт coder'а. Возвращает PASS или
   FAIL с замечаниями по каждому критерию.
4. **При FAIL** передай coder'у замечания verifier'а дословно вместе с
   исходным планом, затем снова вызови verifier.
5. **Максимум 3 итерации** coder → verifier. Если после третьей всё ещё FAIL,
   остановись и отчитайся пользователю: что сделано, какие критерии не
   прошли, последние замечания verifier'а, твоя оценка причины. Новых
   итераций без согласия пользователя не запускай.
6. **Блокеры verifier'а** (нет git baseline, Codex недоступен) — не
   замечания для coder'а: сразу остановись и сообщи пользователю. Если в
   SKIP граничная версия PHP (7.4 или 8.5), это тоже сообщается
   пользователю, но не блокирует PASS.
7. **При PASS** — короткий отчёт пользователю: изменённые файлы, критерии со
   статусами, число итераций, какие версии PHP проверены. В файле задачи
   выставь `Статус: done` и допиши, чем она закрыта. Коммит и push — только
   по просьбе пользователя.

Новые проблемы, найденные по ходу работы (verifier'ом, Codex или
architect'ом) вне текущей задачи, не чини попутно: оформи их как
`tasks/NNN-*.md` по образцу существующих и сообщи пользователю.
