# NBK — курсы Национального банка Казахстана для OpenCart 3

![OpenCart](https://img.shields.io/badge/OpenCart-3.0.x-blue)
![PHP](https://img.shields.io/badge/PHP-7.4%20%E2%80%93%208.5-777bb4)
![License](https://img.shields.io/badge/license-MIT-green)

Расширение валют (`Extensions → Currency`) для OpenCart 3.0.x. Оно загружает
официальные курсы с сайта Национального банка Республики Казахстан
([nationalbank.kz](https://nationalbank.kz)), пересчитывает их относительно
валюты магазина по умолчанию и записывает в стандартную таблицу валют
OpenCart. Цены на витрине, в корзине и в заказах пересчитываются по этим
курсам обычными средствами OpenCart.

Модуль не изменяет файлы ядра и не использует OCMOD-модификации. Он добавляет
только собственные файлы и одно событие (event), поэтому не конфликтует с
другими дополнениями и переживает обновления OpenCart.

## Зачем нужен модуль

Кнопка «Обновить курсы» в стоковом OpenCart 3 (`Система → Локализация →
Валюты`) обращается к API Yahoo Finance, который давно закрыт, поэтому курсы
не обновляются. Магазинам в Казахстане приходится вводить курсы вручную или
ставить сторонние модули, которые часто берут курсы у коммерческих агрегаторов
и правят ядро.

NBK решает эту задачу так:

- курсы берутся из **официального источника**, то есть из RSS-фида Нацбанка
  РК `https://nationalbank.kz/rss/rates_all.xml`;
- штатная кнопка «Обновить» на странице «Валюты» начинает работать и
  загружает курсы Нацбанка;
- курсы можно обновлять **по расписанию через cron**, без входа в админку;
  cron-ссылка защищена секретным ключом;
- к официальному курсу можно добавить **процентную наценку** для каждой
  валюты отдельно, чтобы покрыть спред при конвертации и эквайринге.

## Возможности

- **Официальные курсы НБ РК.** Модуль загружает полный фид
  `rates_all.xml` (все валюты, по которым Нацбанк публикует курс тенге).
- **Любая валюта по умолчанию.** База фида — тенге (KZT), но валютой
  магазина по умолчанию может быть и USD, EUR, RUB или любая другая валюта из
  фида. Кросс-курсы рассчитываются через тенге.
- **Учёт номинала (`quant`).** Часть валют Нацбанк котирует за 10, 100 или
  1000 единиц (например, армянский драм). Модуль делит курс на номинал и
  всегда получает курс за одну единицу.
- **Десятичная запятая в фиде.** Значения вида `5,5` разбираются так же, как
  `5.5`.
- **Штатная кнопка «Обновить».** Модуль подписывается на событие ядра
  `admin/model/localisation/currency/refresh/after`, поэтому кнопка на
  странице «Валюты» и все места ядра, которые вызывают стандартное обновление
  курсов, записывают курсы Нацбанка.
- **Обновление по cron с ключом.** Отдельный URL витрины
  `index.php?route=extension/currency/nbk/refresh&key=<ключ>` с понятными
  ответами (`NBK: ok`, `NBK: failed` и т. д.) и HTTP-кодами, удобными для
  мониторинга. Без верного ключа обновление не выполняется. Готовая
  cron-команда с ключом показывается прямо на странице настроек.
- **Генератор ключа.** Кнопка «Сгенерировать» создаёт криптостойкий
  случайный ключ прямо в браузере. Если ключа ещё нет, он подставляется
  автоматически при открытии настроек.
- **Ограничение cron по IP.** Вызов cron-URL можно дополнительно разрешить
  только с одного IP-адреса (IPv4 или IPv6).
- **Наценки по валютам.** Каждой валюте можно задать свой процент, например
  `EUR:3,5,USD:2,RUB:5`. Дробную часть можно писать через запятую или через
  точку. Отрицательное значение даёт скидку от официального курса.
  Допустимый диапазон — больше −100 % и не больше 100 %.
- **Проверка настроек.** Форма не сохранит наценки с ошибкой формата или
  вне диапазона, некорректный IP, ключ неправильного формата или подделанное
  значение статуса, и покажет, что не так. При обновлении разбор наценок
  работает в мягком режиме: неразборчивые куски пропускаются, и обновление не
  падает.
- **Валюты вне фида не трогаются.** Если в магазине заведена валюта, которой
  нет в фиде Нацбанка, её курс, введённый вручную, остаётся без изменений.
- **Валюта по умолчанию всегда равна 1.** После каждого обновления курс
  валюты по умолчанию принудительно выставляется ровно в `1.00000000`.
- **Защита от записи мусора.** Если фид недоступен, не является корректным
  XML или в нём нет валюты магазина по умолчанию, модуль ничего не записывает
  и оставляет прежние курсы. Курс, который не помещается в колонку базы
  данных или округлился бы до нуля, тоже не записывается.
- **Точная запись в БД.** Курс записывается как строка с фиксированной
  точностью 8 знаков (`sprintf('%.8F')`) под тип `decimal(15,8)`. Очень
  маленькие кросс-курсы не превращаются в экспоненциальную запись, а
  десятичный разделитель всегда точка, даже если на сервере установлена
  локаль с запятой. После записи сбрасывается кеш валют OpenCart.
- **Права доступа выдаются автоматически.** При установке группа
  пользователя, который устанавливает модуль, получает права `access` и
  `modify`, поэтому настраивать права в «Группах пользователей» вручную не
  нужно.
- **Четыре языка админки:** русский (`ru-ru`), английский (`en-gb`),
  казахский (`kk-kz`) и украинский (`uk-ua`).
- **Одна кодовая база для PHP 7.4–8.5.** Модуль работает без предупреждений
  устаревания (Deprecated) на всех этих версиях, включая PHP 8.5.
- **Без правок ядра и без OCMOD.** Только файлы модуля и одно событие,
  которое удаляется вместе с модулем.

## Требования

| Компонент | Требование |
|---|---|
| OpenCart | 3.0.x (проверялся на 3.0.3.x) |
| PHP | 7.4, 8.0, 8.1, 8.2, 8.3, 8.4, 8.5 |

## Установка

### Вариант 1. Копирование файлов (рекомендуется)

1. Скачайте репозиторий
   ([ZIP](https://github.com/sh1sh1n/NBK-opencart/archive/refs/heads/main.zip)
   или `git clone`).
2. Скопируйте каталоги `admin/` и `catalog/` в корень магазина, туда, где
   лежат одноимённые каталоги OpenCart. Файлы попадут в свои папки и ничего
   существующего не перезапишут:

   ```
   admin/controller/extension/currency/nbk.php
   admin/model/extension/currency/nbk.php
   admin/view/template/extension/currency/nbk.twig
   admin/language/{ru-ru,en-gb,kk-kz,uk-ua}/extension/currency/nbk.php
   catalog/controller/extension/currency/nbk.php
   catalog/model/extension/currency/nbk.php
   ```

   Если каталог админки переименован (например, в `admin_xyz`), копируйте
   содержимое `admin/` в него.

3. Файлы `README.md`, `LICENSE`, `CLAUDE.md`, а также каталоги `tests/`,
   `tasks/` и `.claude/` на сервер копировать не нужно: это документация и
   инструменты разработки.

### Вариант 2. Установщик дополнений OpenCart

Установщик OpenCart 3 принимает архив `*.ocmod.zip` с каталогом `upload/`.
Собрать такой архив из репозитория можно так:

```bash
mkdir -p build/upload && cp -R admin catalog build/upload/ && (cd build && zip -r ../nbk.ocmod.zip upload)
```

Затем загрузите `nbk.ocmod.zip` в `Расширения → Установка расширений`.
Архив содержит только файлы, без `install.xml`, поэтому обновлять
модификаторы (`Расширения → Модификаторы → Обновить`) не требуется.

### Активация

1. Откройте `Расширения → Расширения`, в списке типов выберите **«Валюты»**
   (Currency).
2. Найдите **«Национальный банк Казахстана»** и нажмите зелёную кнопку
   **«Установить»**. В этот момент модуль:
   - выдаёт вашей группе пользователей права на `extension/currency/nbk`;
   - регистрирует событие `currency_nbk`, которое подключает модуль к
     штатной кнопке «Обновить».
3. Нажмите **«Редактировать»** (карандаш). Поле **«Ключ защиты»** уже
   заполнено случайным ключом. Выставьте **Статус → Включено** и сохраните
   настройки.
4. Снова откройте настройки: в поле **«Команда cron»** появится готовая
   команда с ключом. Добавьте её в планировщик (см. [Cron](#2-cron-рекомендуется)).
5. Проверьте валюты в `Система → Локализация → Валюты`: коды валют магазина
   (`KZT`, `USD`, `EUR`, `RUB` и т. д.) должны совпадать с кодами в фиде
   Нацбанка (стандарт ISO 4217).
6. Нажмите **«Обновить»** на странице «Валюты» или выполните cron-команду.
   Курсы подтянутся с nationalbank.kz.

## Настройки

Страница настроек: `Расширения → Расширения → Валюты → Национальный банк
Казахстана → Редактировать`.

| Поле | Ключ настройки | Описание |
|---|---|---|
| **Статус** | `currency_nbk_status` | Включает и выключает модуль. В выключенном состоянии кнопка «Обновить» не загружает курсы Нацбанка, а cron-URL отвечает `403 NBK: disabled`. Принимаются только значения `0` и `1`; подделанное значение отклоняется с ошибкой «Некорректное значение статуса!». |
| **Ключ защиты** | `currency_nbk_key` | **Обязательно.** Секретный ключ cron-ссылки: 32–64 латинских буквы и цифры. Кнопка **«Сгенерировать»** создаёт новый случайный ключ (32 символа, 128 бит). Если поле пустое, ключ подставляется при открытии страницы. Ключ сохраняется ровно в том виде, в каком введён, без обрезки пробелов. При неверном формате форма покажет «Ключ защиты должен состоять из 32–64 латинских букв и цифр. Нажмите «Сгенерировать».». |
| **IP для cron** | `currency_nbk_ip` | Необязательно. Если задан, cron-URL выполняется только при запросе с этого IP, а с остальных адресов отвечает `403 NBK: forbidden`. Пусто — разрешён любой источник (но ключ нужен всегда). Принимается корректный IPv4 или IPv6, иначе форма покажет ошибку «Некорректный IP-адрес!». |
| **Наценки по валютам (%)** | `currency_nbk_margins` | Необязательно. Процент надбавки к официальному курсу по каждой валюте, например `EUR:3,5,USD:2,RUB:5`. Подробно см. [Наценки по валютам](#наценки-по-валютам). |
| **Команда cron** | — | Только для чтения. Готовая команда для планировщика с адресом витрины (`HTTPS_CATALOG`) и **сохранённым** ключом. Пока ключ не сохранён, поле пустое и подсказывает: «Сохраните настройки с ключом защиты, чтобы получить cron-команду.» |

Команда cron строится из сохранённого ключа, а не из того, что сейчас
введено в поле. Поэтому после генерации нового ключа сначала сохраните
настройки, затем снова откройте их и скопируйте обновлённую команду.

Вверху страницы есть подсказка со ссылками на управление валютами и на
настройки магазина, где выбирается валюта по умолчанию.

## Как обновляются курсы

### 1. Кнопка «Обновить» в админке

`Система → Локализация → Валюты → Обновить`.

В стоковом OpenCart 3 эта кнопка вызывает `admin/model/localisation/currency`
→ `refresh()`, которая работает с закрытым API Yahoo и никаких курсов не
получает. При установке модуль регистрирует событие на **завершение** этого
метода (`…/refresh/after`). Сразу после отработки стокового кода вызывается
`refreshEvent()` модуля, который загружает фид Нацбанка и записывает курсы.
Так как событие срабатывает последним, записанные значения — это курсы
Нацбанка.

Кнопке ключ не нужен: доступ к ней уже ограничен правами администратора.

Для сборок OpenCart, где обновление вызывает метод `currency()` у
расширения валют (`extension/currency/<код>/currency`), в контроллере
оставлен такой метод, и он делает то же самое.

### 2. Cron (рекомендуется)

URL витрины:

```
https://ваш-магазин.kz/index.php?route=extension/currency/nbk/refresh&key=ВАШ_КЛЮЧ
```

Готовую команду можно скопировать с поля «Команда cron» на странице настроек.
Она имеет вид:

```bash
curl -s "https://ваш-магазин.kz/index.php?route=extension/currency/nbk/refresh&key=ВАШ_КЛЮЧ"
```

Пример записи в `crontab`: обновлять курсы каждые 3 часа, в 5 минут часа.

```
5 */3 * * * curl -s "https://ваш-магазин.kz/index.php?route=extension/currency/nbk/refresh&key=ВАШ_КЛЮЧ" > /dev/null
```

Вызывать URL с верным ключом можно сколько угодно раз: каждый вызов просто
перезаписывает курсы актуальными значениями. Запрос без ключа или с неверным
ключом отклоняется сразу, до обращения к сайту Нацбанка и к базе данных.

Проверки выполняются в таком порядке: статус модуля → IP (если задан) →
ключ → загрузка фида и запись курсов.

#### Ответы cron-URL

| HTTP-код | Тело ответа | Что это значит |
|---|---|---|
| `200` | `NBK: ok` | Курсы загружены и записаны. |
| `403` | `NBK: disabled` | Модуль выключен в настройках (Статус → Отключено). |
| `403` | `NBK: forbidden` | Ключ не передан, неверен или ещё не сохранён в настройках; либо задан «IP для cron», а запрос пришёл с другого адреса. |
| `502` | `NBK: failed` | Курсы не записаны: фид недоступен (сеть, таймаут 30 секунд), ответ не является корректным XML или в фиде нет валюты магазина по умолчанию. Прежние курсы остаются как были. |

Ответы и коды стабильны, поэтому их удобно проверять в мониторинге.
Например, `curl -sf` вернёт ненулевой код выхода при `403` и `502`:

```bash
curl -sf "https://ваш-магазин.kz/index.php?route=extension/currency/nbk/refresh&key=ВАШ_КЛЮЧ" || echo "NBK refresh failed" | mail -s "NBK" admin@example.com
```

## Как считаются курсы

### Шаг 1. Разбор фида

Каждый элемент `<item>` фида Нацбанка содержит:

- `<title>` — код валюты (`USD`, `EUR`, `AMD`…);
- `<description>` — сколько тенге стоят `quant` единиц валюты;
- `<quant>` — номинал (1, 10, 100, 1000). Если тега нет, номинал равен 1.

Модуль строит таблицу «сколько тенге стоит 1 единица валюты»:

```
kzt_per[X] = description / quant
```

Тенге (`KZT`) — база фида, поэтому модуль добавляет `kzt_per[KZT] = 1` сам.
Если в фиде вдруг окажется элемент `KZT`, он игнорируется: база всегда
равна 1, иначе исказились бы все кросс-курсы. Элементы без кода, без курса,
с нулевым или отрицательным курсом либо номиналом пропускаются.

### Шаг 2. Пересчёт относительно валюты по умолчанию

В OpenCart поле `value` валюты означает, сколько единиц этой валюты дают за
1 единицу валюты по умолчанию. Модуль считает его так:

```
value[X] = kzt_per[валюта_по_умолчанию] / kzt_per[X]
```

и затем, если для валюты задана наценка:

```
value[X] = value[X] × (1 + наценка[X] / 100)
```

Обновляются только те валюты, которые заведены в магазине **и** есть в фиде.
Каждый курс перед записью проверяется на то, что он поместится в колонку
`decimal(15,8)` положительным числом (подробнее — в разделе
[Поведение в особых случаях](#поведение-в-особых-случаях)). В конце курс
валюты по умолчанию принудительно записывается как `1`.

### Пример: валюта по умолчанию — тенге

Фид: USD = 500, EUR = 550, AMD = 12,5 за 10, RUB = 5,5, CNY = 70.
Наценки: `USD:2,EUR:3,5`.

| Валюта | Тенге за 1 ед. | `value` без наценки | Наценка | Записанный `value` |
|---|---|---|---|---|
| KZT | 1 | 1 | — | `1.00000000` |
| USD | 500 | 0.002 | 2 % | `0.00204000` |
| EUR | 550 | 0.00181818 | 3,5 % | `0.00188182` |
| AMD | 1,25 | 0.8 | — | `0.80000000` |
| RUB | 5,5 | 0.18181818 | — | `0.18181818` |
| CNY | 70 | 0.01428571 | — | `0.01428571` |

Товар за 10 000 ₸ покупатель увидит за $20,40 вместо $20,00: наценка 2 %
заложена в курс.

### Пример: валюта по умолчанию — доллар

Тот же фид, без наценок:

| Валюта | Расчёт | `value` |
|---|---|---|
| USD | — | `1.00000000` |
| KZT | 500 / 1 | `500.00000000` |
| EUR | 500 / 550 | `0.90909091` |
| RUB | 500 / 5,5 | `90.90909091` |
| AMD | 500 / 1,25 | `400.00000000` |

## Наценки по валютам

Наценка — это процент, на который курс валюты увеличивается относительно
официального. Она нужна, когда магазин получает оплату в иностранной валюте,
а банк конвертирует её по курсу хуже официального, или когда нужно заложить
комиссию эквайринга.

### Формат

```
КОД:процент, КОД:процент, ...
```

- **КОД** — трёхбуквенный код валюты, регистр не важен (`eur` = `EUR`).
- **процент** — число. Дробную часть можно писать через **запятую или
  точку**: `3,5` и `3.5` означают одно и то же.
- Пары разделяются запятой. Пробелы вокруг `:` и `,` допускаются.
- Допускаются знак `+`, запись без целой части (`.5`) и знак `%` после
  числа (`USD:2%`).
- **Отрицательное** значение уменьшает курс, то есть даёт скидку от
  официального курса.
- Наценка должна быть **больше −100 и не больше 100**. При −100 % курс стал
  бы нулевым, а при меньшем значении — отрицательным; наценка больше 100 %
  (больше чем двойной курс) почти наверняка опечатка. Допустимы, например,
  `-50`, `-99,99` и `100`; значения `-100`, `-100,0`, `-150`, `101` форма не
  сохранит.
- Разрешена одна завершающая запятая.
- Пустое поле означает, что наценок нет.

Запятая после цифры всегда относится к числу, а не к разделителю пар, потому
что код валюты не может начинаться с цифры. Поэтому строка `EUR:3,5,USD:2`
однозначно читается как «EUR — 3,5 %, USD — 2 %».

### Примеры

| Ввод | Результат |
|---|---|
| `EUR:3,5,USD:2,RUB:5` | EUR +3,5 %, USD +2 %, RUB +5 % |
| `EUR:3.5, USD:2, RUB:5` | то же самое |
| `usd : 1,25 %` | USD +1,25 % |
| `USD:-1` | USD −1 % (скидка от официального курса) |
| `USD:-99,99` | USD −99,99 % (допустимо) |
| `USD:100` | USD +100 %, курс удваивается (верхняя граница включительно) |
| `USD:2,` | USD +2 % (завершающая запятая допустима) |
| *(пусто)* | наценок нет, все валюты по официальному курсу |
| `USD2` | ошибка формата: нет двоеточия |
| `EURO:3` | ошибка формата: код должен состоять из трёх букв |
| `USD:abc` | ошибка формата: процент не является числом |
| `USD:-100` | ошибка диапазона: наценка должна быть больше −100 % |
| `USD:101` | ошибка диапазона: наценка должна быть не больше 100 % |
| `EUR:3,USD:-150` | ошибка диапазона: у USD наценка меньше −100 % |
| `USD:-150,USD:2` | ошибка диапазона: проверяются все пары, даже если последнее значение корректно |

При ошибке форма не сохраняется и показывает сообщение. Сначала проверяется
формат: «Некорректный формат наценок! Пример: EUR:3,5,USD:2». Если формат
верный, но наценка какой-либо валюты вне диапазона, выводится «Наценка
должна быть больше -100% и не больше 100%!».

### Правила применения

- Валюты, не указанные в списке, идут по **точному официальному курсу**.
- Валюта магазина **по умолчанию никогда не наценивается**: её курс всегда
  равен 1.
- Если одна валюта указана дважды, действует последнее значение.
- Наценка `0` равносильна её отсутствию.
- Наценка для валюты, которой нет в магазине или в фиде, ни на что не
  влияет.
- Во время обновления (по кнопке или cron) разбор работает в мягком режиме:
  если в базе оказалось значение, сохранённое в обход формы, модуль
  применит все корректные пары и пропустит мусор, а не прервёт обновление.
- Если наценка дала бы нулевой или отрицательный курс (после округления до
  8 знаков), модуль её не применяет и записывает официальный курс этой
  валюты. Так обрабатываются значения −100 % и меньше, сохранённые прежними
  версиями модуля. Нулевые курсы, записанные ими раньше, исправятся при
  первом же обновлении.
- Близкая к −100 % наценка, например `-99.9999999`, форму проходит, но если
  курс с ней округляется до нуля, при обновлении она тоже отбрасывается.
- Если с наценкой курс не помещается в колонку `decimal(15,8)` (достигает
  10 000 000), наценка не применяется, записывается официальный курс.
- Верхняя граница 100 % проверяется только формой. Наценки больше 100 %,
  сохранённые раньше, при обновлении применяются, пока курс помещается в
  колонку; сохранить форму с таким значением без исправления нельзя.

## Поведение в особых случаях

| Ситуация | Что делает модуль |
|---|---|
| Модуль выключен | Кнопка «Обновить» не трогает курсы. Cron отвечает `403 NBK: disabled`. |
| Cron вызван без ключа, с неверным ключом или с ключом-массивом (`key[]=…`) | `403 NBK: forbidden`. Фид не запрашивается, база не трогается. |
| Ключ ещё не сохранён (например, сразу после обновления со старой версии) | Cron отвечает `403 NBK: forbidden`, пока настройки не сохранены с ключом. Кнопка «Обновить» в админке работает. |
| Сайт Нацбанка недоступен или отвечает дольше 30 секунд | Ничего не записывается, прежние курсы остаются. Cron отвечает `502 NBK: failed`. |
| Фид пришёл битым (не XML) | Ничего не записывается, ошибки libxml подавляются. Cron отвечает `502 NBK: failed`. |
| Валюты магазина по умолчанию нет в фиде (и это не KZT) | Пересчитать курсы не через что, поэтому ничего не записывается. Cron отвечает `502 NBK: failed`. |
| В фиде есть элемент `KZT` | Игнорируется: курс тенге как базы всегда равен 1. |
| В магазине есть валюта, которой нет в фиде | Её курс не меняется, остаётся введённый вручную. |
| В фиде есть валюта, которой нет в магазине | Игнорируется. Чтобы её использовать, заведите валюту с тем же кодом в `Система → Локализация → Валюты`. |
| Валюта в фиде котируется за 10/100/1000 единиц | Курс делится на номинал. |
| Курс в фиде записан с запятой (`5,5`) | Разбирается как `5.5`. |
| Отдельная запись фида повреждена (нет курса, курс 0, номинал 0, пустой код) | Эта запись пропускается, остальные обрабатываются. |
| Очень маленький кросс-курс (например, KZT при базе USD) | Записывается с 8 знаками после точки, без экспоненты. |
| Кросс-курс не помещается в колонку `decimal(15,8)` даже без наценки (10 000 000 и больше) или округляется до нуля | Валюта пропускается, остаётся её прежний курс. Остальные валюты обновляются, cron отвечает `200 NBK: ok`. |
| Наценка −100 % или меньше сохранена в базе (например, прежней версией модуля) | Наценка не применяется, записывается официальный курс валюты. В форме значение показывается как есть, но сохранить его без исправления нельзя. |
| На сервере установлена локаль с десятичной запятой (`LC_NUMERIC`) | Не влияет: курс всегда записывается с точкой. |

## Безопасность

- **Cron-URL защищён обязательным ключом.** Без ключа модуль остаётся
  закрытым (fail-closed), отключить проверку нельзя. Запрос с неверным
  ключом отклоняется до обращения к фиду и к базе, поэтому посторонний не
  может нагружать сервер и nationalbank.kz обновлениями, даже зная адрес.
- Ключ сравнивается функцией `hash_equals()`, то есть за постоянное время:
  подобрать его по времени ответа нельзя.
- Ключ генерируется в браузере через `crypto.getRandomValues()` (128 бит).
  Если браузер его не поддерживает, кнопка «Сгенерировать» отключается, а не
  использует предсказуемый генератор.
- Ключ передаётся в URL, поэтому он попадает в `crontab` и может попасть в
  access-логи веб-сервера и прокси. Не публикуйте cron-команду. Если ключ
  утёк, сгенерируйте новый, сохраните настройки и замените команду в
  `crontab`: старый ключ сразу перестанет работать.
- **IP-замок** — дополнительный слой защиты поверх ключа; он проверяется до
  ключа. Адрес сравнивается с `REMOTE_ADDR` точно. Если сайт работает за
  обратным прокси, CDN или балансировщиком (Cloudflare, nginx-прокси и
  т. п.), `REMOTE_ADDR` будет адресом прокси, а не сервера с cron. Учитывайте
  это или ограничивайте доступ средствами веб-сервера.
- Значения настроек выводятся в форму с HTML-экранированием: Twig в
  OpenCart 3 работает без автоэкранирования, поэтому модуль экранирует их
  сам. Подделанные запросы с массивами вместо строк и произвольные значения
  статуса отклоняются при сохранении.
- Источник курсов зашит в код (`https://nationalbank.kz/rss/rates_all.xml`)
  и не меняется через настройки.
- Изменение настроек требует права `modify` на `extension/currency/nbk`.
- Запись в базу идёт только по заранее известным кодам валют из таблицы
  `currency`, с экранированием кода и числом фиксированного формата.

## Обновление и удаление модуля

### Обновление

Перезапишите файлы модуля новыми версиями (FTP, SSH или `git pull` в
отдельном каталоге с последующим копированием). Настройки хранятся в базе и
при замене файлов сохраняются. Переустанавливать модуль нужно, только если в
описании новой версии сказано, что изменилась регистрация события.

**Обновление с версии без ключа защиты.** После выкладки файлов cron
начнёт отвечать `403 NBK: forbidden`, пока в настройках нет ключа. Чтобы
включить его снова:

1. Откройте настройки модуля. Поле «Ключ защиты» уже заполнено
   сгенерированным ключом.
2. Нажмите **«Сохранить»**.
3. Снова откройте настройки, скопируйте новую команду из поля «Команда
   cron» и замените ею старую команду в `crontab`.

Переустанавливать модуль при этом не нужно. Если в сохранённых наценках
есть значения вне диапазона (−100; 100], форма попросит их исправить.

### Удаление

`Расширения → Расширения → Валюты → Национальный банк Казахстана →
Удалить` (красная кнопка). При удалении:

- снимается событие `currency_nbk`, и кнопка «Обновить» возвращается к
  стоковому поведению;
- OpenCart удаляет настройки модуля (`currency_nbk_*`), включая ключ;
- курсы валют, уже записанные в таблицу `currency`, **остаются** как есть.

После этого файлы модуля можно удалить с сервера, а cron-задачу — из
`crontab`.

## Устройство модуля

Структура репозитория повторяет дерево OpenCart:

```
admin/
  controller/extension/currency/nbk.php   настройки, validate(), install/uninstall,
                                          refreshEvent() и currency()
  model/extension/currency/nbk.php        загрузка фида, расчёт, наценки, запись в БД
  view/template/extension/currency/nbk.twig  форма настроек и генератор ключа
  language/ru-ru|en-gb|kk-kz|uk-ua/extension/currency/nbk.php  переводы
catalog/
  controller/extension/currency/nbk.php   cron-точка refresh(): статус, IP, ключ
  model/extension/currency/nbk.php        та же модель, что в admin (байт-в-байт)
tests/
  run.sh                 единая точка запуска всех проверок
  static.php             инварианты и правила переносимости
  smoke.php              прогон модуля на заглушках OpenCart, без БД и сети
  fixtures/rates_all.xml фид в формате Нацбанка с круглыми курсами
tasks/                   бэклог задач
```

### Ключевые точки

| Что | Где |
|---|---|
| Код расширения | `nbk` (тип `currency`) |
| Маршрут настроек | `extension/currency/nbk` |
| Настройки | `currency_nbk_status`, `currency_nbk_key`, `currency_nbk_ip`, `currency_nbk_margins` |
| Событие | код `currency_nbk`, триггер `admin/model/localisation/currency/refresh/after`, действие `extension/currency/nbk/refreshEvent` |
| Cron-маршрут | `extension/currency/nbk/refresh&key=<currency_nbk_key>` (витрина) |
| Источник курсов | `https://nationalbank.kz/rss/rates_all.xml` |
| Запись в БД | `UPDATE oc_currency SET value, date_modified WHERE code`, затем `cache->delete('currency')` |

Модели в `admin/` и `catalog/` намеренно одинаковые: обновление по кнопке
идёт через admin-модель, а по cron — через catalog-модель, и обе должны
считать курсы одинаково.

## Совместимость с PHP

Модуль рассчитан на серверы, где одновременно работают разные версии PHP, и
использует одну кодовую базу для всех:

- синтаксис не новее PHP 7.4;
- функции PHP 8.x используются только при проверке `function_exists()`;
- явные флаги у `htmlspecialchars()` и `html_entity_decode()`, потому что
  значения по умолчанию в 7.4 и 8.1+ различаются;
- код не выдаёт Deprecated ни на одной версии. В частности, `curl_close()`
  вызывается только на PHP < 8.0: начиная с 8.0 он ничего не делает, а в 8.5
  объявлен устаревшим, и его предупреждение попадало бы в ответ cron.

Версии 7.4 и 8.1–8.5 прогоняются автоматическими тестами (см. ниже).

## Разработка и тесты

Все проверки запускаются одной командой:

```bash
tests/run.sh
```

Скрипт выполняет:

1. **Статические проверки** (`tests/static.php`): в дереве только файлы
   модуля и документация (без файлов ядра и OCMOD); модели `admin/` и
   `catalog/` совпадают; одинаковый набор языковых ключей во всех четырёх
   локалях и отсутствие пустых строк; сбалансированные блоки Twig; значения
   настроек выводятся в шаблоне без повторного экранирования (оно делается в
   контроллере); генератор ключа использует `crypto.getRandomValues`, а не
   `Math.random`; отсутствие API из PHP 8.x и устаревших конструкций; числа
   форматируются независимо от локали (`%F`, а не `%f`); UTF-8 без BOM,
   переводы строк LF, без закрывающего `?>`.
2. **`php -l`** всех PHP-файлов на каждой установленной версии PHP. Любой
   вывод, кроме «No syntax errors», считается ошибкой, включая
   compile-time Deprecated. Если список файлов пуст, не удалось его получить
   или проверено меньше файлов, чем найдено, это тоже провал, а не ложный
   успех.
3. **Smoke-тесты** (`tests/smoke.php`) на каждой версии: модуль
   загружается с заглушками OpenCart (реестр, конфиг, БД, кеш, запрос,
   ответ), `curl_exec()` отдаёт `tests/fixtures/rates_all.xml`, и
   проверяются записанные курсы, наценки и их диапазон, переполнение
   колонки, ответы cron (статус, IP, ключ), валидация и экранирование формы.
   Любой notice, warning или deprecation валит прогон.

По умолчанию проверяется матрица `7.4 8.1 8.2 8.3 8.4 8.5`. Можно указать
версии явно:

```bash
tests/run.sh 7.4 8.5
```

Отсутствующая версия PHP отмечается как `SKIP`, а не пропускается молча.
Для CI есть строгий режим, в котором `SKIP` считается провалом:

```bash
NBK_REQUIRE_ALL=1 tests/run.sh
```

Недостающие версии PHP на macOS ставятся через Homebrew:

```bash
brew install shivammathur/php/php@8.5
```

Код выхода: `0`, если все выполненные проверки прошли, иначе `1`.

### Правила кода

- Стиль OpenCart 3: табы в PHP, два пробела в Twig, `array()` вместо `[]`,
  без закрывающего `?>`, UTF-8 без BOM, LF.
- Модели `admin/` и `catalog/` меняются синхронно и остаются идентичными.
- Новый языковой ключ добавляется во все четыре локали с настоящим
  переводом.
- Пользовательские значения в шаблоне экранируются явно.
- Любое изменение поведения сопровождается тестом в `tests/smoke.php`.
- Ядро OpenCart не правится, OCMOD не используется.

### Бэклог

Задачи оформляются файлами `tasks/NNN-*.md`: описание, воспроизведение,
варианты решения, критерии приёмки и то, чем задача закрыта.

## Известные ограничения

- Ограничение cron по IP поддерживает только один адрес.
- Ключ передаётся в строке запроса, поэтому может оказаться в логах
  веб-сервера (см. [Безопасность](#безопасность)).
- Модуль не хранит историю курсов и не показывает дату курса Нацбанка:
  в таблице `currency` обновляется только поле `date_modified`.
